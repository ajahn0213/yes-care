# YES 심방 · YES Pastoral Care

남가주 사랑의교회 YES 청년부 심방(尋訪) 예약·목양 관리 웹앱입니다.
청년은 회원가입 없이 링크로 들어와 가능한 시간을 골라 신청하고, 목사님은 Google 캘린더와 연결된 관리자 화면에서 일정·이력·비공개 메모를 관리합니다.

---

## 1. 무엇이 들어 있나요

**신청자 화면**
- `/` 소개: 마음을 방문하는 시간, 尋訪·心訪, 나눌 수 있는 이야기, 만나는 장소
- `/book` 일정 고르기: 가능한 날짜만 누를 수 있고, 시간은 1시간 단위로 보입니다 (LA 시간, 일광절약시간 자동 반영)
- `/book/details` 만남 방식, 신청자 정보, 개인정보 이용 안내 동의
- `/book/confirm` 최종 확인 → [심방 예약 확정하기]
- `/booking/success` 완료 화면, 심방을 준비하는 세 가지 마음, 내 캘린더에 추가(.ics)
- `/booking/manage/[토큰]` 메일 링크로 들어와 내 예약 확인·시간 변경·취소

**목회자 화면** (`/admin`, Google 로그인)
- 대시보드: 오늘·이번 주·이번 달 심방 수, 다음 심방, 최근 신청, 최근 변경·취소, 지난 심방 정리, 월별 완료 수
- 심방 예약: 다가오는/지난/취소 목록, 검색, 직접 등록(전화·카톡으로 정한 일정)
- 예약 상세: 완료·미진행 표시, 일정 변경, 취소, 정보 수정, 확정 메일 다시 보내기, 기록 영구 삭제, 캘린더 불일치 고치기
- **비공개 목양 메모**: 메모, 추후 연락 필요, 다음 심방. 예약 정보와 따로 저장하고, 메일과 캘린더에는 넣지 않습니다
- 캘린더: 월간 보기
- 대상자: 사람별 심방 이력, 추후 연락 필요 모아 보기
- 설정: Google 캘린더 연결·테스트·동기화 점검, 요일별 가능 시간, 휴무일, 예약 규칙, 장소·Meet·초대, 알림 메일, 보관 기간, 설치 점검

## 2. 기술 선택과 이유

| 부분 | 선택 | 이유 |
|---|---|---|
| 화면·서버 | Next.js 15 (App Router), JavaScript, 일반 CSS | 이미 쓰시는 과제점검·새일꾼반 앱과 같은 방식입니다. GitHub 웹에서 파일만 올려도 배포됩니다 |
| 저장소 | **Upstash Redis (기존 yes-app-db 재사용)** | 이미 연결해 두신 무료 저장소라 새 서비스 가입이 필요 없습니다. 모든 키가 `care:`로 시작해 다른 앱과 섞이지 않습니다. `SET NX` 잠금으로 동시 예약을 막습니다 |
| 로그인 | Google 로그인 (`ADMIN_EMAILS`에 있는 계정만) | 캘린더 연결에 Google 인증이 어차피 필요해서 하나로 합쳤습니다 |
| 캘린더 | Google Calendar API (공식 REST) | FreeBusy로 바쁜 시간만 확인하고, 일정은 Events API로 만들기·옮기기·지우기 합니다 |
| 메일 | Gmail 앱 비밀번호 (nodemailer) | 새일꾼반 앱에서 이미 쓰고 있는 방식입니다. 무료이고 하루 약 500통까지 보낼 수 있습니다 |
| 배포 | Vercel Hobby (무료) + Vercel Cron (하루 1번) | 지금 쓰시는 그대로입니다 |

**Supabase를 쓰지 않은 이유.** 기획안은 Supabase PostgreSQL을 "검토"하라고 했습니다. 지금 규모(목회자 1명, 한 달 수십 건)에서는 이미 연결된 Upstash로 충분합니다. 새 계정, 마이그레이션, RLS 정책을 따로 관리할 부담도 없습니다. 권한 검사는 모두 서버에서 하고, 브라우저는 데이터베이스에 직접 접근하지 못합니다. 목회자가 여러 명이 되거나 통계 질의가 복잡해지면 그때 Supabase로 옮기는 것이 좋습니다. `lib/store.js` 한 파일만 바꾸면 됩니다.

**TypeScript·Tailwind를 쓰지 않은 이유.** 기존 두 앱과 같은 구조여야 목사님이 한 가지 방식으로 세 앱을 관리하실 수 있습니다.

**Google 예약 일정(Appointment Schedule)을 검토한 결과.** Google 캘린더의 예약 일정은 Google이 제공하는 예약 페이지 링크입니다. 그 예약 페이지를 만들거나 바꾸거나, 예약 내역을 가져오는 공개 API는 없습니다. 그래서 다음 요구사항을 채울 수 없습니다.
- 우리 디자인과 문구
- 마음의 준비 안내
- 만남 방식과 장소 선택
- 목양 이력과 비공개 메모
- 예약 관리 링크

그래서 **독자적인 예약 화면 + Google Calendar API(FreeBusy·Events)** 방식으로 만들었습니다. 지원되는 공식 API만 사용합니다.

## 4. Google Cloud OAuth 설정 (15분)

1. https://console.cloud.google.com 에 **캘린더를 연결할 Google 계정**으로 들어갑니다.
2. 위쪽 프로젝트 선택에서 **새 프로젝트**를 만듭니다. 이름은 `YES 심방`으로 합니다.
3. **API 및 서비스 → 라이브러리**에서 `Google Calendar API`를 찾아 **사용**을 누릅니다.
4. **Google 인증 플랫폼(OAuth 동의 화면)**을 엽니다.
   - 앱 이름 `YES 심방`, 지원 이메일은 본인 이메일로 넣습니다.
   - 대상(User type)
     - 교회 Google Workspace 계정(@sarang.com 등)으로 캘린더를 쓰시면 **내부(Internal)**를 고르세요. 검증이 필요 없고 연결이 만료되지 않습니다.
     - 개인 Gmail이면 **외부(External)**를 고릅니다.
   - **데이터 액세스(범위)**에 다음을 추가합니다: `openid`, `.../auth/userinfo.email`, `.../auth/calendar.events`, `.../auth/calendar.freebusy`
5. 외부(External)를 고르셨다면 **대상 → 앱 게시(Publish app)**를 눌러 **프로덕션** 상태로 바꿔 주세요.
   - ⚠️ "테스트" 상태로 두면 **7일마다 캘린더 연결이 끊깁니다.**
   - 게시 후 처음 연결할 때 "Google에서 확인하지 않은 앱" 경고가 보일 수 있습니다. 목사님 본인 앱이니 **고급 → YES 심방(으)로 이동**을 누르면 됩니다.
   - 이 앱에 로그인하는 사람은 목회자뿐이라 Google 검증 심사는 필요 없습니다.
6. **클라이언트 → 클라이언트 만들기 → 웹 애플리케이션**을 고릅니다.
   - 승인된 리디렉션 URI: `https://(앱 주소)/api/auth/google/callback`
     - 예: `https://yes-care.vercel.app/api/auth/google/callback`
   - 주소를 바꾸면 여기도 같이 바꿔야 합니다.
7. 만들어진 **클라이언트 ID**와 **클라이언트 보안 비밀번호**를 Vercel에 넣습니다.

**권한 범위**
- `calendar.freebusy`는 바쁜 시간만 확인합니다. 일정 제목이나 내용은 읽지 않습니다.
- `calendar.events`는 심방 일정을 만들고, 옮기고, 지울 때 씁니다.

## 5. Vercel 환경 변수

`.env.example`을 참고해 **Settings → Environment Variables**에 넣고 **Redeploy** 하세요.

| 이름 | 필수 | 설명 |
|---|---|---|
| `KV_REST_API_URL`, `KV_REST_API_TOKEN` | ✅ | yes-app-db를 연결하면 자동으로 생깁니다 |
| `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET` | ✅ | 4장에서 만든 값 |
| `ADMIN_EMAILS` | ✅ | 관리자 Google 계정 (쉼표로 여러 명). 명단에서 빼면 즉시 접근이 막힙니다 |
| `APP_URL` | ✅ | `https://yes-care.vercel.app` (끝에 `/` 없이) |
| `GMAIL_USER`, `GMAIL_APP_PASSWORD` | ✅ | 새일꾼반 앱과 같은 값을 써도 됩니다 (yes.sarang@gmail.com + 앱 비밀번호) |
| `SESSION_SECRET` | 권장 | 영문·숫자 40자 이상 아무 문자열. 한 번 정하면 바꾸지 마세요. 바꾸면 모두 로그아웃되고 캘린더를 다시 연결해야 합니다 |
| `CRON_SECRET` | 권장 | 영문·숫자 32자 이상. 있어야 매일 아침 "내일 심방" 안내 메일이 나갑니다 |
| `ADMIN_PASSWORD` | 선택 | Google 로그인이 안 될 때 쓰는 비상용 비밀번호 로그인 |
| `MAIL_FROM_NAME` | 선택 | 보내는 사람 이름 (기본값: YES 심방) |

**만드는 법:** `SESSION_SECRET`과 `CRON_SECRET`은 https://1password.com/password-generator 같은 곳에서 기호를 빼고 40자를 만들어 붙여 넣으면 됩니다.

## 6. 매일 알림 (Vercel Cron)

`vercel.json`에 **매일 15:05 UTC**로 설정되어 있습니다. LA 시간으로 여름에는 오전 8:05, 겨울에는 오전 7:05입니다.
- 내일 심방이 있는 신청자에게 **하루 전 안내 메일**을 한 번만 보냅니다.
- 목회자에게 **내일 일정 요약**을 보냅니다.

Vercel Hobby(무료)는 하루 1번 cron을 허용하므로 추가 비용이 없습니다.

## 7. 보안과 개인정보

- **신청자에게 보이는 것:** 가능한 시간만 보입니다. 캘린더 일정의 제목·내용·바쁜 시간 자체는 서버 밖으로 나가지 않습니다.
- **예약 관리 링크**
  - 추측할 수 없는 32자 토큰을 씁니다. 서버에는 HMAC 해시로 저장하고, 메일 재발송용 원본은 AES-256-GCM으로 암호화해 둡니다.
  - 토큰은 URL 쿼리가 아니라 요청 본문으로 서버에 보냅니다.
  - 관리 화면은 `Referrer-Policy: no-referrer`로 열립니다.
- **캘린더 연결 정보:** Google refresh token은 AES-256-GCM으로 암호화해 저장합니다. 화면 응답에는 절대 포함하지 않습니다.
- **목양 메모:** `care:note:*` 키에 예약과 따로 저장합니다. 관리자 API로만 읽을 수 있고, 메일·캘린더·신청자 화면 어디에도 나가지 않습니다.
- **기도 제목·나눌 이야기**
  - 관리자 화면에서만 보입니다.
  - 캘린더 일정 설명과 모든 메일(목회자 알림 포함)에 넣지 않습니다.
- **관리자 로그인**
  - Google 계정 이메일이 `ADMIN_EMAILS`에 있어야 합니다.
  - 세션은 httpOnly·SameSite 쿠키로 14일 동안 유지됩니다.
  - 모든 요청마다 명단을 다시 확인합니다.
- **요청 위조(CSRF) 방어:** 관리자 변경 요청은 같은 출처(Origin)와 전용 헤더가 있어야 받습니다. 신청과 관리 요청도 같은 출처만 받습니다.
- **반복 신청 방지**
  - IP는 해시로만 기록합니다.
  - 같은 IP에서 시간당 12건(교회 와이파이에서 여럿이 신청해도 괜찮도록), 같은 이메일로 하루 4건까지 신청할 수 있습니다.
  - 한 사람이 앞으로 잡아 둘 수 있는 예약은 2건까지입니다.
  - 숨은 입력칸으로 봇을 막습니다.
  - 관리자 비밀번호 로그인은 15분에 8번까지 시도할 수 있습니다.
- **중복 예약 방지**
  - 예약 확정은 Redis 잠금 안에서 처리합니다.
  - 잠금 안에서 캘린더 바쁜 시간과 앱 예약을 **다시 조회**한 뒤에 확정합니다.
  - 동시에 같은 시간을 신청하면 한 명만 확정되고, 다른 한 명은 "다른 시간을 골라 주세요" 안내를 받습니다.
- **캘린더가 실패하면 확정하지 않음**
  - 캘린더 일정을 만들지 못하면 예약을 저장하지 않고 "확정되지 않았어요"라고 안내합니다.
  - 저장에 실패하면 만든 캘린더 일정을 되돌립니다.
  - 연결이 만료되면 신청 화면은 "준비 중"으로 바뀌고, 관리자 화면에 빨간 안내가 뜹니다.
- **불일치 복구:** [설정 → 동기화 점검]이 캘린더에서 지워졌거나 시간이 바뀐 심방을 찾습니다. 찾은 것은 다시 만들기, 캘린더 시간으로 맞추기, 앱 시간으로 되돌리기, 취소 처리 중 하나로 고칩니다.
- **보관과 삭제**
  - 보관 기간(기본 24개월)이 지난 기록은 [설정]에서 한 번에 영구 삭제합니다.
  - 한 사람이 삭제를 요청하면 그 예약에서 **기록 영구 삭제**를 누르면 됩니다.
- **로그:** 서버 로그와 운영 기록에 이름·이메일·기도 제목을 남기지 않습니다. 외부 분석 도구도 쓰지 않습니다.
- **긴급 안내:** 모든 화면 아래와 모든 메일에 911과 988(Suicide & Crisis Lifeline) 안내가 있습니다.

## 8. 기능 테스트 결과

실제 Google·Gmail 대신 **똑같이 동작하는 가짜 서버**를 띄워서 확인했습니다. 가짜 서버는 Google OAuth, Calendar FreeBusy·Events, Upstash REST, SMTP입니다. 결과는 **64개 항목 모두 통과**입니다.

- 관리자
  - 명단 밖 Google 계정은 거부됩니다.
  - 로그인 없이는 관리자 API와 메모에 접근할 수 없습니다.
  - 전용 헤더가 없는 변경 요청은 차단됩니다.
- 캘린더 연결
  - 연결 전에는 신청 화면이 "준비 중"으로 보입니다.
  - 연결한 뒤 refresh token은 어떤 응답에도 없습니다.
- 가능 시간
  - 24시간 안의 시간은 나오지 않습니다.
  - **캘린더에 바쁜 일정이 있으면 그 시간과 앞뒤 준비 시간이 빠집니다.**
  - 일정 내용("병원 진료")은 응답에 없습니다.
- 일광절약시간: 11/1 전 10:00은 17:00Z, 11/1 후 10:00은 18:00Z로 정확히 바뀝니다.
- 예약 확정
  - 캘린더에 같은 시간의 비공개 일정이 생깁니다.
  - 일정에 기도 제목이 없습니다.
  - 신청자에게 초대장이 갑니다.
  - 온라인이면 Meet 링크가 생깁니다.
  - DB에 이벤트 ID가 저장되고, 확정된 시간은 목록에서 빠집니다.
- 메일
  - 신청자 확정 메일 제목이 맞고, LA 시간(PDT/PST)으로 표시됩니다.
  - 관리 링크와 마음의 준비가 들어 있습니다.
  - 목회자 알림이 갑니다.
  - **어떤 메일에도 기도 제목·나눌 이야기·목양 메모가 없습니다.**
- **동시 신청:** 두 명이 같은 시간을 동시에 신청하면 한 건만 확정되고, 캘린더에도 한 건만 생깁니다.
- 관리 링크
  - 틀린 토큰으로는 열람할 수 없습니다.
  - 일정을 바꾸면 캘린더도 같이 옮겨집니다.
  - 취소하면 캘린더 일정이 삭제되고, 신청자와 목회자에게 메일이 갑니다.
- 장애 상황
  - 캘린더 일정 생성이 실패하면 "확정되지 않았어요"라고 안내하고 DB에도 저장하지 않습니다.
  - Google 오류가 나면 "불러오지 못했어요"라고 안내합니다.
  - **연결이 만료되면** 신청 화면이 준비 중으로 바뀌고 관리자에게 안내가 뜹니다. 다시 연결하면 복구됩니다.
- 관리자 기능
  - 직접 등록하면 캘린더에도 만들어집니다. 같은 시간이 겹치면 경고합니다.
  - 목양 메모를 쓰면 목록에는 표시만 되고 메모 내용은 나오지 않습니다. 대상자 목록에 '추후 연락'이 표시됩니다.
  - 캘린더에서 지운 일정은 동기화 점검에서 찾아내고, 다시 만들 수 있습니다.
- 매일 알림
  - CRON_SECRET이 없으면 실행되지 않습니다.
  - 하루 전 안내와 목회자 요약이 나가고, 같은 안내를 두 번 보내지 않습니다.
- 화면
  - iPhone 크기(Chromium 모바일 에뮬레이션)에서 소개 → 일정 → 정보 → 확인 → 완료 → 관리 링크 → 시간 변경까지 진행했습니다.
  - 데스크톱 관리자 화면 전체를 확인했고, 콘솔 오류는 0건입니다.
  - ⚠️ 실제 iPhone Safari와 실제 Google 계정 연결은 배포 후 체크리스트 ⑧로 확인해 주세요.
